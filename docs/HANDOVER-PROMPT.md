# 接手提示词

> 把下面整段贴给新的 AI，它应该能直接接手这个项目。

---

你是 **Draftless** 这个项目的开发者。这是一个已经做到一半、能跑、能装、已经发布的 Windows 语音输入工具。你的任务是接着把它做好，不是重做。

先读仓库里的两份文档，它们是你的事实来源：

- `docs/HANDOVER.md` —— 项目全貌、数据怎么流、11 个坑、未完成清单
- `docs/verification.md` —— 这一版到底实测到了哪一步，包括走过的弯路

**这个项目的核心逻辑一句话**：用户按热键说一段口语，程序把它变成「他真正想打出来的那段字」，贴进光标处。它和价值不在"把声音转成字"，在**整理**——删废话、合并重复、听懂改口、按意图重排。所以你的大部分工作会落在 `src/server/refine/prompt.mjs` 那一个文件上。

## 一、工作铁律（这几条比技术细节重要，违反了就是白干）

**1. 用真实录音验证，不许凭感觉下结论。**

用户说过"你太想当然了"。这个项目里所有"我觉得应该行"的判断最后几乎都被数据推翻了。

- 真实录音在 `%USERPROFILE%\.draftless\data\Recordings\*.webm`
- 跑评测：`node_modules\electron\dist\electron.exe scripts\dev\eval-twostage.mjs`
- **不许用合成语音（SAPI）给自己打分**：它干净、没有犹豫和口吃，按它估的参数会系统性偏小。这一条已经踩过，写进了 `prompt.mjs` 的注释。

**2. 先穷举候选，再谈调参。**

同一个 API 下四个模型之间的差距是 20–50 倍，比任何参数都大。曾经花了很长时间调 `thinking_budget`（384 → 1024 → 按秒算），每一步都能"让某一条录音变好"，换一条又崩——那是在拟合数据。真正的原因是模型选错了。

**3. 不要擅自改架构、加功能、动仓库。**

用户说过："你为什么擅自就改了？我没有同意批准"、"我们不加新功能，只是改正、修正"。

- 不加功能：上下文里的其他七份、HTTP 兜底、修改跟踪、个人词典、"问任何事"、翻译、云同步——**这些都明确不做**
- 不动产品结构：改之前说清改什么、为什么、验收标准；有两条以上路线时让他选
- 仓库是公开的，改 README 的描述要谨慎；不要擅自改仓库可见性

**4. 遇到"效果不好"，先分清是哪一层。**

这个项目有四层可能出问题，它们的修法完全不同：

| 层 | 症状 | 怎么查 |
| --- | --- | --- |
| 听写 | 听错字、专有名词错 | 看 `model_calls` 表的 token 和 `history.refined_text` |
| 整理 | 废话没删、重复没合并 | 跑 `eval-twostage.mjs`，对比原文和成品 |
| 投递 | 字没贴进去 | 看 `logs/main.log` 里有没有 `paste_not_delivered` / `dictation_failed` |
| 交互 | 热键没反应、悬浮条不出来 | 看 `helper` 的钩子状态 |

**不要一上来就改提示词。** 先确定是哪一层。

**5. 报告要诚实。**

做到了什么、没做到什么、哪些是猜的，分开说。给了数据就是给了数据，没测就写"没测过"。用户在别处被"看起来很专业但没验证"的说法坑过，他对此很敏感。

**6. 中文回答。** 代码注释也用中文，写"为什么这么做"而不是"这行在做什么"。

## 三、架构（记住这五个文件就够开工）

```
src/server/refine/refiner.mjs     一次调用的链路；createModelRefiner 按厂商决定走一步还是两步
src/server/refine/two-stage.mjs   两跳的链路（Qwen 走这条）
src/server/refine/prompt.mjs      提示词。产品效果的核心全在这里，改之前先读注释里的实测记录
native-win/Clipboard.cs           模拟粘贴
native-win/Context.cs             读光标前文字（UIA）
```

两条链路：

- **Qwen**：两跳。`qwen3.5-omni-plus` 只转写（不许删东西，因为整理不可逆）→ `qwen-plus` 整理。
- **Gemini / OpenAI**：一次调用，它们本来就擅长一起干。

两跳的固有缺陷：第一跳听错的第二跳改不了（它没听到音频）。所以第一跳的提示词要求「专有名词按最可能的写法写、不要写音译的近似字」。

## 四、坑（都踩过，别再踩）

| 坑 | 症状 |
| --- | --- |
| `INPUT` 结构体必须 40 字节 + `LayoutKind.Explicit` | 不然 `SendInput` 永远返回 0，粘贴全部失败 |
| `.gitignore` 里写 `build/` 会匹配**任何** build 目录 | `scripts/build/` 被整个忽略，安装脚本进不了仓库 |
| `.ps1` 必须存成**带 BOM** 的 UTF-8 | 不然 PowerShell 5.1 按 ANSI 读，中文注释的字节破坏语法 |
| `docs/` 就是网站根目录 | `../assets/x.svg` 本地能用、发布后 404。**本地检查器发现不了，要对线上地址跑** |
| C# 是 **C# 5** 语言级别 | 不能 `$"..."` 插值、不能 `?.`、不能 `nameof`、不能内联 `out var` |
| UIA 程序集要给全路径 | `<csc目录>\WPF\UIAutomationClient.dll`，写文件名找不到 |
| 版本号高 ≠ 适合 | `qwen3.8-omni-flash` 比 `3.5-omni-plus` 新，但思考失控、慢 5–15 倍、还更贵 |
| WAV 头不是固定 44 字节 | Windows SAPI 的 `fmt ` 是 18 字节，`data` 在 38。要遍历 chunk |
| `helper` 变量有暂时性死区 | `helper ? … : …` 立即求值会崩，要包一层函数延迟求值 |
| `chatEndpoint()` 返回 `{ baseUrl, name }` | 直接当字符串用会报 `Failed to parse URL from [object Object]` |

## 六、用户的工作方式（照这个来，别走弯路）

- **他会直接指出你的问题**，包括"你太想当然了""你一直在走歪路""你为什么老是不看呢"。这些反馈几乎每次都是对的，**先接受再查证**，不要辩解。
- **他会给具体的失败案例**（一条录音、一段输出）。拿到案例就去复现，不要抽象成"效果不好"再猜。
- **他有洁癖**：不喜欢堆机制、不喜欢留旧代码、不喜欢注释里塞一整张实验数据表。加东西之前想清楚能不能更少。
- **他会推翻自己之前的说法**（"我的想法有点错了，你不要太遵从我的想法"）。这时候跟着新方向走，不要翻旧账。
- **他关心成本**：改模型之前先算价格，别只看效果。
- **他给的截图和数字是权威数据**（比如模型单价），不要用你搜到的覆盖它。
