# 02 代码还原

## 混淆形态

应用自己的 JS 用 javascript-obfuscator 处理过，特征是开头一个字符串数组、一个解码函数、一段旋转数组的自执行代码，正文里所有字符串都换成 `_0x46a1d4(0xbe)` 这样的查表调用。

被混淆的文件共 21 个：

- `dist/main/index.js`（主进程，636 KB，2843 条字符串）
- `dist/main/worker/opusWorker.js`、`chunkSessionWorker.js`
- `dist/preload/index.mjs`
- `dist/renderer/static/js/` 下 17 个（应用逻辑；其余约 60 个是语言包和第三方库，未混淆）

没有用到控制流平坦化、调试保护、自我防御这几项（webcrack 对应的变换改动数都是 0）。所以还原后的代码结构和原始打包产物一致，只是局部变量名丢了。

另有一层更浅的遮掩：部分请求头名字写成十六进制串，运行时用一个小函数转回 ASCII。例如 `582d417574686f72697a6174696f6e` 就是 `X-Authorization`。

## 为什么必须先还原

REA 的 JS 分析是纯语法的，不执行代码。字符串被藏进查表调用后，它认不出 IPC 通道名、接口路径这些字面量。两次分析的对比：

| 指标 | 原件（`ev_746a49c3…`） | 还原后（`ev_675220c1…`） |
| --- | --- | --- |
| 字面量 IPC 通道 | 8 | 112 |
| 动态表达式通道 | 38 | 45 |
| 主进程 handler | 44 | 146 |
| contextBridge 接口 | 0 | 3 |
| 暴露的接口成员 | 0 | 8 |

## 还原步骤

1. **解包**：`tools/asar-extract.mjs`。只读解析 asar 头，按前缀导出文件，校验条目名防止路径逃逸。
2. **去混淆**：`tools/deobfuscate.sh` 调 webcrack 2.16.0。它在沙箱里执行字符串解码函数，把查表调用替换回字面量。
3. **导入改名**：`tools/rename-imports.mjs`。把 `import { app as _0x50ee68 }` 这类绑定改回 `app`，用 babel 的作用域改名，不改语义。
4. **组装可读树**：`tools/build-readable-tree.sh`。生成与原 `dist/` 同结构的目录，被混淆的文件换成还原版，其余原样拷贝。

REA 自带的 `recover_javascript_sources` 做的是同类工作，但只支持 Linux x64，本机用不了，所以第 2 步用了外部工具。webcrack 要求 Node 22 或 24，本机是 26，于是在 `_work/tooling/` 里局部装了 Node 24。

## 两份输入各管什么

- **原件** `_work/asar/dist/`：发行包的真实字节。身份、哈希、"包里有没有某个文件"以它为准。
- **可读树** `_work/readable/dist/`：派生产物。行为分析以它为准，文档里的 `readable:文件:行号` 都指它。重新生成后行号可能变化。

## 还原后仍然缺的

- 局部变量名和函数名仍是 `_0x…` 或单双字母，只有类的方法名、对象属性名、字符串是原样的。好在这个代码库的方法名很规整，靠方法名就能读懂大部分逻辑。
- 没有 source map，原始文件划分恢复不了。主进程是一个 2 万行的单文件。
- 状态机（悬浮条用的 XState）被打包后展开得很长，状态图没有逐个状态画出来。
